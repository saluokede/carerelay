# D8 · 建档表单的字段校验（2026-11-05）

## 用户看到的问题

我在 `/elders/new` 上把联系电话、住址、照护人、基础病都填成 `1`，出生日期选了 `2027/01/01`，点「建档并继续」：按钮没反应，页面也没有任何提示。截图见 `docs/screenshots/11-form-validation.png`（修好后的样子）。

## 根因

AI 翻 `DischargeImportView.vue`，里面只有两处判断：

- 提交按钮 `:disabled="busy === 'create' || !form.name.trim()"` —— 只拦空姓名；
- `createAndContinue()` 直接把值发给后端，前端不做任何格式校验。

于是「姓名填了、其余全是垃圾值」这种最常见的录入错误一路到底，只在后端炸出一个 400。`error.value` 的提示又离出错字段很远，护士根本看不出该改哪一格。

## 改法

1. 抽出 `validate()`，逐字段产出 `errors`（`Record<string, string>`），规则：
   | 字段 | 必填 | 规则 |
   |---|---|---|
   | 姓名 | ✅ | 2–20 字；不能是一串数字 |
   | 出生日期 | ✅ | 不能晚于今天；年份 ≥1900；年龄 ≤120（风险评分要用年龄） |
   | 联系电话 | ✅ | `^1[3-9]\d{9}$`，提示"随访要打这个号" |
   | 住址 | ✅ | ≥4 字，提示"请写到街道门牌" |
   | 照护人电话 | 选填 | 填了就必须是 11 位手机号 |
   | 基础病 / 过敏 | 选填 | 填了不能是纯数字 |
2. 每个字段包一层 `data-field`，输入框按 `errors.x` 加 `.invalid` 红框，字段下方显示 `.field-error`。
3. `attempted` 置真后 `watch(form, …)` 实时重算：改对一处，那一条即时消失，不用再点一次提交。
4. 错误得贴着字段出现，这条是我提的。顶部汇总条 `.form-alert`：「还有 4 处需要补上：出生日期、联系电话、住址、基础病」；点提交失败时 `focusFirstError()` 滚到第一个出错字段并聚焦。
5. 日期上限用本地时区的 `todayIso`（`toISOString()` 在 UTC+8 的晚上会差一天）。

## 实测（真跑，非截图摆拍）

填写 `姓名=1 / 出生日期=2027-01-01 / 电话=1 / 住址=1 / 基础病=2` 后点提交：

```
errors: ["姓名不能是一串数字", "出生日期不能晚于今天", "请填 11 位手机号，例如 13800000001",
         "住址请写到街道门牌，至少 4 个字", "基础病请写名称，例如：高血压、糖尿病"]
alert:  "还有 5 处需要补上：姓名、出生日期、联系电话、住址、基础病"
```

把五项改成合法值（`新来的老人 / 1950-03-05 / 13800000009 / 阳光街道 7 号楼 1 单元 202 / 高血压，糖尿病`）后，等一个渲染帧再读 DOM：`errors: []`、`alert: null`、`.invalid` 元素数 `0`——**边改边消**。

我按这两次读取验收：截图可以摆，`errors` 列表和 `.invalid` 的计数摆不了。

## 这一处值得在答辩里讲

校验不是「体验优化」，是数据质量的闸门：基础病和过敏是风险评分与用药冲突判定的输入，联系方式是随访能不能落地的唯一通道。前端把 `1` 拦下来，比后端回一个 400 少走一次往返；**填错的人当场知道错在哪一格**。
