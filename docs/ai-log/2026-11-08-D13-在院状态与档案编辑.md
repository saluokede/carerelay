# D13 · 档案加"在院状态"与床位，并且能改

> 我看过「基本情况」卡片后提了需求（m06047）："是不是应该还有床位、是否住院，等一系列要素，并且应该方便修改。"
> 这条提得对：出院老人会**再次住院**，这时候还在催家属做家里的任务是不对的；护士交接也需要知道床号与科室。加哪些字段、接口按字段打补丁、界面进哪一栏，都由我定；AI 补了其中若干函数和页面片段，我改定后合并、验收。

## 一、加了什么

**数据**（`V5__elder_care_status.sql`）
- `care_status`：`HOME` 居家随访 / `HOSPITALIZED` 住院中 / `CLOSED` 已结案
- `bed_no`、`hospital`、`department`、`admit_date`（最近一次入院）

**接口**
- `PATCH /api/v1/elders/{id}`：按字段打补丁（传了才改），空字符串表示清空，`null` 表示不改。
- 权限：`RoleRules` 把 `/api/v1/elders/**` 的写操作统一收进"仅医护"，家属 PATCH 返回 `code=403 该操作仅限医护人员`（已实测）。

**界面**
- 详情页「基本情况」右上角：状态 pill（居家随访/住院中/已结案）+「编辑档案」按钮。
- 有住院信息时多一行"住院信息 · 医院 · 科室 · 12-3 床 · 入院日期"。
- 「编辑档案」是抽屉式表单：基本信息一栏 + 在院状态一栏（状态、床号、医院、科室、入院日期），底部保存。
- 家属端：老人 `HOSPITALIZED` 时不再显示"照着做"任务与到点提醒，改为一条横幅——"老人在住院中…等接回家、护士重新确认后，任务会自动恢复"。

## 二、连带的业务规则

`TaskSweeper` 增加一条：**住院中的老人整体跳过**——任务保留在库里，但既不判逾期、也不升级预警/工单。
这条规则第一版没写全：只跳过了"升级"，没跳过"判逾期"，测试任务（昨天、PENDING、住院中）仍然被标成了 MISSED。我看这是漏改，要求补上，做法是把住院老人 id 集合放到标记循环之前取、循环内 `continue`；复测 `pendingScanned=7, markedMissed=0`，那条任务保持 PENDING。

## 三、实测

改完我按下面这几条场景验了一遍，结果照原样记：

| 场景 | 结果 |
|---|---|
| `PATCH /elders/1 {careStatus:HOSPITALIZED, bedNo:12-3, hospital:市第一人民医院, department:神经内科}` | `code=0`，库里中文正确（`--default-character-set=utf8mb4` 查得） |
| 家属 PATCH | `code=403 该操作仅限医护人员`，库里未被改 |
| 编辑抽屉改床号 12-3 → 15-2 | 保存后卡片立即显示"15-2 床"，表单关闭 |
| 住院中 + 昨天未完成任务 | 巡检 `markedMissed=0`，任务保持 PENDING |
| 家属端（住院中） | 显示"老人在住院中"，隐藏任务与提醒 |

## 四、还没做（明确记下）

1. **计划生成不受在院状态影响**：住院中仍然可以生成 30 天计划（只是不催办）。严格说应该提示"人在住院，建议出院后再签发"。
2. 家属端只隐藏了任务，没有隐藏"记一句"——这是故意的，住院期间的家属反馈也有价值。
3. 床位变化没有留历史（只保存当前值）。要做"每次住院一条记录"需要独立的 admission 表。
