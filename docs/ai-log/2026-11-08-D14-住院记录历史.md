# D14 · 住院记录（每次住院一条，床位不再只存当前值）

> 用户在看完 D13 的"还没做"后点了这一条：床位只存当前值，没有每次住院的历史表。

## 一、为什么单独建表

`elder_profile.bed_no / hospital / department` 是**当前值**：老人第二次住院时，第一次的医院、科室、床号、住了几天就被覆盖了。护士交接、家属复盘、以及"这半年住了几次院"这类问题都答不上来。

所以：档案上保留当前值（列表、卡片、家属端只关心"现在在哪"），历史放进 `elder_admission`。

## 二、数据与接口

`V6__elder_admission.sql`

| 字段 | 说明 |
|---|---|
| `elder_id` | 老人 |
| `hospital / department / bed_no` | 这一次住院的医院、科室、床号 |
| `admit_date`（必填） / `discharge_date` | 入院、出院（空＝还在院） |
| `reason` | 入院原因/诊断，选填 |
| `status` | `IN_HOSPITAL` / `DISCHARGED` |

接口（全部医护可用，`RoleRules` 新增 `/api/v1/admissions`）：

- `GET /api/v1/elders/{id}/admissions` — 按入院日期倒序
- `POST /api/v1/elders/{id}/admissions` — 不带 `dischargeDate` 就是"现在在院"：会把档案同步成 `HOSPITALIZED` 并写入床位/医院/科室/入院日期；带 `dischargeDate` 就是**补登历史**，不动档案
- `POST /api/v1/admissions/{id}/discharge` — 办出院：写回出院日期、状态置 `DISCHARGED`、档案回到 `HOME` 并清空当前床位

规则与防呆：

- 同一老人**同时只能有一条在院记录**（再登记会被拒："已经有一条在院记录，请先给那一笔办理出院"）。
- 出院日期不能早于入院日期。
- 每次登记/出院都写审计：`ADMISSION_CREATE` / `ADMISSION_DISCHARGE`。
- 列表里返回 `days`（住院天数，含首尾），前端直接显示"共 9 天"。

## 三、界面

老人详情左栏「基本情况」下面新增「住院记录」卡片：

- 每条：医院 · 科室 · 床号 + 状态 pill（在院/已出院）+ `2026-11-01 ~ 2026-11-05 · 共 5 天 · 再入院：伤口渗液、发热`。
- 右上「登记住院」：抽屉式表单（医院/科室/床号/入院日期/出院日期/原因），说明写清"只填入院日期＝现在在院；连出院日期一起填＝补登历史"。
- 在院那条右侧有「办理出院」，点完档案立刻回到"居家随访"，床位清空。

## 四、实测

| 步骤 | 结果 |
|---|---|
| 初始列表 | 0 条 |

## 五、还没做

- 住院记录与出院小结（`discharge_record`）没有关联字段——理论上"这次住院"出院时应该生成一条出院小结，现在只能靠日期人工对应。
- 没有"住院次数/累计住院天数"的统计，护士台没展示。
- 删除/更正住院记录没有界面入口（只能走数据库），真实使用中录错是常事，后面要补。
