# D2 · 执行环：打卡判读与预警升级（2026-11-04）

## 本轮目标

让「住院医嘱变成家属今天能照着做的一张清单，做了有人看，不对了有人管」这条链真正跑起来：
出院小结 → 计划 + 任务 → 家属打卡 → 判读 → 预警 → 工单 → 护士处置 → 审计。

## AI 参与的部分

分工的边界在这三行里：症状文字和语音交给 AI 判读，数值指标和照片它不碰，每一档都要写明失败时退到哪里。

| 环节 | AI 做什么 | 不做什么 | 失败时怎么办 |
| --- | --- | --- | --- |
| 症状文字/语音判读 | 把「胸口有点闷，还出了很多汗」归到 NORMAL / MEDIUM / HIGH 三档，给家属一句人话回应 | 不诊断、不判断病因、不给药 | 关键词规则兜底，`judge_source=RULE` 如实标注 |
| 数值指标 | **不参与** | —— | 血压/血糖/体温/血氧全部走代码规则 |
| 照片 | 不做判读 | —— | 记为"待护士目视"，`rule_code=PHOTO_PENDING`，24 小时内人工确认 |

## 关键设计：判读分流

同一个数字必须永远得到同一个结论，否则护士不敢用。所以：

- **数值走 `VitalRules`（纯代码）**：收缩压 ≥180 / 舒张压 ≥110 → HIGH；≥160/100 → MEDIUM；<90 → HIGH；血糖 ≥16.7 或 <3.9 → HIGH；体温 ≥38.5 → HIGH；血氧 <92% → HIGH。命中即写 `alert_event.rule_code`，护士一眼看出跨了哪条线。
- **文字走模型**：`prompts/checkin_judge.v1.md`，输出严格 JSON `{status, level, rule_code, message}`。模型这一侧只交这四个字段，多一句解释都不要。
- **模型不可用** → `keywordJudge()`：先做「去空格标点」归一化，再查红旗词；并有**组合式红旗**（含"胸" + 闷/紧/压/疼/痛 → 按胸痛处理），避免"胸口 闷"这种断词漏判。
- **安全网**：模型判 NORMAL 但原文命中红旗 → 强制升级 HIGH，`rule_code=KEYWORD_RED_FLAG`。

## 人工介入点（这轮改了 AI/规则的地方）

1. **首次关键词判读把人话判成正常**：原文「胸口有点闷」不含连续词"胸闷"，旧规则判 NORMAL。我判定这不可接受，规则退回重写：加归一化 + 组合式红旗。这是本轮的**规则修订**，不是数据修补。
2. **预警标题信息量太低**：原来所有打卡异常都叫「打卡异常」，护士要在列表里读 detail 才知道是什么。改法是不再共用一句，按规则前缀生成「打卡异常：血压 / 血糖 / 体温 / 血氧 / 症状反馈」，护士扫列表就能分出是哪类。
3. **MEDIUM 不自动开工单**是我有意留的：工单是"必须有人处置"的队列，如果中等风险也进队列，护士会被稀释到只处理工单、不处理预警。

## 踩坑

这轮真跑时撞上的几条：

- `.mvn-settings.xml` 里的 `localRepository` 还指向旧项目 `D:/学习/传智杯/.m2repo`，导致 `-Dmaven.repo.local` 被 settings 覆盖后落到 `C:\Users\37783\.m2`（沙箱拒绝）。修：改成 `D:/学习/tools/_dl/m2` 并用 `-s` 显式指定。
- 打包时报 `Unable to rename ...jar`：上一轮的 java 进程占着 jar。`Get-CimInstance Win32_Process` 被沙箱拒绝，改用 `Get-Process java` 看 `Path` 判断是不是自己的进程，再 Stop。
- `Start-Process` 起的 java 会在 pwsh 命令结束时被回收，后端必须用后台作业（`run_in_background`）拉起。
- PowerShell 控制台中文乱码只是显示编码问题，接口 JSON 本身正常（DB 里 `checkin.judge_note` 中文完好）。
