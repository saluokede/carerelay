## 踩坑与修法

1. **后端被"用后即收"**：`Start-Process` 起的 java 会在 pwsh 命令结束时被回收，表现为"上一个命令里
   health=UP，下一个命令就 ECONNREFUSED"。正解是用后台作业（`run_in_background`）跑 java，作业在进程就在。
2. **脚本执行策略**：`& .\scripts\db-start.ps1` 报"未对文件进行数字签名"。正解：同一命令内先
   `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force` 再调用。
3. **MySQL 在沙箱外**：数据目录在 `C:\carerelay-mysql-root`，必须提权一次才能起库（与之前一致）。
4. **验收脚本三处形状假设错了**（这是 AI 写脚本时的假设问题，不是服务的）：
   - 抽取响应的结构化字段叫 `data`，不是 `structured`；
   - `/ai/ping` 原来直接返回裸 Map，没走统一信封 → 顺手改成 `ApiResult` 并换掉遗留的"养老院活动"提示词；
   - 30 天结局返回的是 `Report` 对象（有 `familyMd`），不是脚本原先假设的 `markdown`。

## 教训

- "前端藏了按钮"不是权限。角色校验必须落在服务端，且要有一条测试专门验证"带 query 参数不能绕过"。
- 验收脚本要按真实响应形状写，宁可先探一次再断言；否则失败的是测试，不是产品。
- 评估一个环境的健康度，别只看"刚才还好"，要看**进程由谁持有**——作业没了，服务就没了。
