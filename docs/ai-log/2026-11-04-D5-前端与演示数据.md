页面、路由、脚本这一轮由我定下结构与接口的口径，AI 按这两条补了其中若干函数、样式和页面片段，我改定后合并；我亲手落地的动作只有两处——批了一次提权构建，最后开浏览器定界面。

## 踩坑与修法

1. **包体积**：首版 1,063.98 kB / gzip 350 kB。原因不在代码，在 `main.ts` 里 `app.use(ElementPlus)`——全量注册，页面一个组件都没用上。
   既然样式全走自制的类，就把依赖撤了，重构建 **108.93 kB / gzip 42.48 kB**。撤依赖这个取舍是我拍的，具体改动 AI 出的初稿，我复核后合并。
2. **构建在沙箱里跑不动**：esbuild 子进程 `spawn EPERM`，往 `%TEMP%` 写又 `Access is denied`。
   两件事分开办：提权一次（这次提权是我批的，只批了这一次），`TEMP`/`TMP` 指到仓库内 `.tmp/tmp`。之后构建通过。
3. **代理 502**：转发时带上原请求的 `content-length`/`transfer-encoding` 会让 undici 抛 `fetch failed`；
   PowerShell 5.1 的 `Expect: 100-continue` 也会被拒。两处都在 `serve-frontend.mjs` 里剔除。
4. **打卡静默放过**（真缺陷）：演示脚本只给 `valueJson` 不给 `kind`，172/104 被当成"已完成"记 NORMAL。
   已改为从载荷里读 `kind`；修后实测 `ABNORMAL / MEDIUM / BP_HIGH_160_100`，并建出 `alert_event`。
5. **浏览器不可用**：本机 Electron provider 无可用二进制，"打开页面截图"这条路走不通。
   验收因此拆成两半：`vue-tsc --noEmit` 0 错误、`vite build` 成功、经 4173 代理的接口冒烟，这三项由 AI 跑、结果由我核；
   界面能不能看，交给我本人打开 `http://127.0.0.1:4173` 定。

## 教训

- 依赖不是"加了再说"：一个 import 就是 350 kB 的 gzip 体积，评委会看。这条是撤 Element Plus 换来的。
- 演示数据必须走真实接口，不能写 SQL 塞。"绿案例顺利、红案例升级"这条故事线，
  只有真跑过才知道模型会在红案例里连续追问同一个问题——这也是可以讲的真实行为。
- 沙箱里的构建问题优先怀疑子进程与临时目录，而不是代码。
