# D5 · 2026-11-04 · 前端八页与演示数据编排

## 这一轮输入的意图

后端四个环都跑通了，但作品还没"能给人看"：旧仓库的前端是上一个选题（银龄聚）的页面，
本作品的护士台、家属端、打卡页、随访页、复盘页都还不存在。

本轮要解决两件事：

1. 用与后端同等的工程标准，把 10 个页面写出来（适老化：大字、高对比、少术语）。
2. 把四个环串成**一条能被讲解的故事**，做成可重复执行的脚本，而不是手工点出来的截图。

## 踩坑与修法

1. **包体积**：首版 1,063.98 kB / gzip 350 kB。原因不在代码，在 `main.ts` 里 `app.use(ElementPlus)`。
   既然页面全用自制样式类，直接移除依赖，重构建 **108.93 kB / gzip 42.48 kB**。
2. **构建在沙箱里跑不动**：esbuild 子进程 `spawn EPERM`，写 `%TEMP%` 又 `Access is denied`。
   提权一次 + `TEMP/TMP` 指到仓库内 `.tmp/tmp` 后通过。
3. **代理 502**：转发时带上原请求的 `content-length`/`transfer-encoding` 会让 undici 抛 `fetch failed`；
   PowerShell 5.1 的 `Expect: 100-continue` 也会被拒。两处都在 `serve-frontend.mjs` 里剔除。
4. **打卡静默放过**（真缺陷）：演示脚本只给 `valueJson` 不给 `kind`，172/104 被当成"已完成"记 NORMAL。
   已改为从载荷里读 `kind`；修后实测 `ABNORMAL / MEDIUM / BP_HIGH_160_100`，并建出 `alert_event`。
5. **浏览器不可用**：本机 Electron provider 无可用二进制，"打开页面截图"这条路走不通。
   验收改为 `vue-tsc --noEmit` 0 错误 + `vite build` 成功 + 经 4173 代理的接口冒烟；
   视觉验收交给用户本人打开 `http://127.0.0.1:4173`。

## 教训

- 依赖不是"加了再说"：一个 import 就是 350 kB 的 gzip 体积，评委会看。
- 演示数据必须走真实接口，不能写 SQL 塞。"绿案例顺利、红案例升级"这条故事线，
  只有真跑过才知道模型会在红案例里连续追问同一个问题——这也是可以讲的真实行为。
- 沙箱里的构建问题优先怀疑子进程与临时目录，而不是代码。
