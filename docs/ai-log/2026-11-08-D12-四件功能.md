## 一、逾期任务自动升级（补上执行环的洞）

**问题**：任务只有 `PENDING/DONE/MISSED`，但没有任何东西把 `PENDING` 变成 `MISSED`。家属不打卡，系统就安静地什么也不发生——这和"最怕没人接着"的立论自相矛盾。

**做法**（`backend/.../checkin/TaskSweeper.java`）：
- `@EnableScheduling` + `@Scheduled(cron = "0 5 * * * *")`，每小时第 5 分钟扫一次；开关 `cr.sweep.enabled`。
- 判定：昨天及以前的 `PENDING` 全部标 `MISSED`；今天的只标"已过时间段 + 30 分钟宽限"的。
- 升级：按老人统计近 3 天 `MISSED` 数——≥3 建 **HIGH 预警 + PENDING 工单**，≥2 建 MEDIUM 预警；`ruleCode=TASK_MISSED`，同一天同一老人只报一次。
- 手动补跑：`POST /api/v1/tasks/sweep`（医护），与定时任务同一条代码路径。

**实测**：`{"pendingScanned":274,"markedMissed":268,"alertsRaised":4,"ticketsRaised":4}`。

## 二、A4 交接单（`/elders/:id/print`）

- 顶层独立路由（不套 AppLayout），`@page { size: A4 portrait; margin: 10mm }`，打印时隐藏工具栏与背景。
- 内容：老人/照护人/基础病/过敏、出院日期/医院/主要诊断/随访安排/复诊、出院带药表（含疗程）、30 天目标、红线框、落款签字。
- 底部固定一句："本单由「医养接力站」生成，内容来自出院小结结构化档案与护士签发的 30 天计划；AI 只做整理与解释，剂量与阈值由系统规则判定。"

## 三、AI 调用记录（`/ai-records`，仅管理员）

- 后端 `GET /api/v1/ai/records?scene=&limit=`，只返回长度不返回原文（避免把提示词与病历原文暴露在列表里）。
- 前端：四个统计卡（近 100 次调用 / 真实模型调用 / 耗时中位数 / 失败数）+ 场景过滤 + 明细表（场景、模式、模型、耗时、输入输出字数、结果、时间）。
- 评审问"AI 到底在不在工作"，这一页就是回答——谁调的、什么场景、花多久、成没成。

## 四、计划会诊留言

- 表 `plan_comment`（V4 迁移），护士与医生都能留，`author_role` 区分；600 字上限；写 `PLAN_COMMENT` 审计。
- 界面上「会诊意见」卡片在计划页右侧，显示"医生不能签发，但可以在这里提出调整建议"。

## 五、这一轮踩到的坑

这四个坑都是 AI 在实现时撞上的，改法记在下面。

1. **Tomcat 起不来**：`java.io.tmpdir` 指向 `%TEMP%`，沙箱回落到 workspace-write 后 `AccessDeniedException`。启动加 `-Djava.io.tmpdir=D:\学习\医养接力站\.tmp\tmp`。
2. **留言时间显示"—"**：`insert` 后没回读数据库生成的 `created_at`，补一次 `selectById`。
3. **留言列表不显示**：`load()` 只 `Promise.all` 了计划与任务，忘了把 `listPlanComments` 加进去——接口有数据、页面空白，典型的"只改了一半"。
4. 打包 `Unable to rename ...jar`：旧 java 占着 jar，先 `Stop-Process` 再打。
