# 06 · 指导老师改版说明（工作台整体改版）

> 本文件记录 2026-11 按指导老师意见对「医养接力站」做的整体改版：以前端改版包（`医养接力站-全栈代码.zip`）为新的界面与接口规格，在原 Spring Boot 工程里实现，最终仍打包成免安装演示包。
>
> 分工也记一句：改版意见来自指导老师，界面和接口以改版包为准，实现由 AI 落在原 Spring Boot 工程里；能不能用，看第七节的验证记录，那几项是我在本机逐项跑的。

## 一、改版前后对照

| 维度 | 改版前 | 改版后 |
|---|---|---|
| 登录方式 | 手机号登录，家属端另开 `/family` 页输出院卡编号 | 统一登录页，账号 + 密码，点角色标签自动填充；注册页只开放出院老人自助注册 |
| 角色 | 社区护士、家庭医生、家属、管理员 | 医院主治医生、社区照护员、出院老人、管理员（演示只保留这四个账号） |
| 界面 | Vue 单页应用，护士工作台为首页 | 原生 HTML + JS 工作台，四端各有首页与左栏导航 |
| 接口 | `/api/v1/**`（旧链路完整保留） | 新增 `/api/**` 一整套新版接口，旧接口不动 |
| 数据 | `app_user` / `elder_profile` 等原业务表 | 新增 `users` / `elders` / `plans` / `followups` / `alerts` / `messages` / `revisits` / `records` / `announcements` / `ai_logs` 十张表（Flyway `V8`），与旧表并存 |
| 交付 | 4191 免安装包（JRE + MySQL + 前后端） | 同一个 4191 免安装包，换成新版前端与后端 jar |

## 二、前端

- 静态资源直接取改版包的 `public/`：`index.html`（登录 + 注册）、`workbench.html`（工作台壳）、`assets/css/app.css`、`assets/js/{api.js,ui.js,views.js}`。
- 这些文件打包进 jar 的 `BOOT-INF/classes/static/`，同时复制一份到演示包的 `app\web`；`server.jar` 在 4191 上提供它们，并反代 `/api`。
- 登录页的角色标签、四端左栏菜单、各业务弹窗都由 `views.js` 按角色渲染；`api.js` 统一走 `fetch('/api'+path)`，碰上 401 就清会话、退回登录页。

## 四、AI 能力

- `StationAiService` 管规则引擎和模型调用之间的降级：
  - 风险评分按 `score = 80 − 预警数×8 − max(0, 70 − 完成率)×0.5 − 急性病种 5` 算，截断在 30~95；预警没闭环且完成率 <60% 判高危。
  - 方案草案、随访摘要、分诊、家属问答、康复动作指导各有规则模板。
  - 只要配了模型（管理员在「系统配置」页填地址 / 模型 / Key，或设 `CR_AI_API_KEY`）就走 `AiGateway#chat`；返回的 JSON 解析不了或者超时，自动降级到规则，界面上标注 AI 来源。
- 本机实测：`/api/ai/summary` 走真实模型能返回自然语言摘要；没有 Key 时 4ms 内返回规则摘要。

## 五、数据与迁移

- `V8__station_module.sql` 建十张表并写入演示数据：4 个账号（hospital / nurse / elder1 / admin）、4 位老人（王桂兰 高危、张淑珍 高危、李建国 低危、赵德海 低危）、3 条待签发方案、5 条随访、3 条预警（2 未闭环 1 已闭环）、3 条记录、2 条留言、1 条公告、1 条复诊；随后的迁移 V9 删掉 doctor 与 family 两个演示账号。
- 旧库升级时 Flyway 只补 V8，旧表与旧数据不受影响（演示包内的 MySQL 数据目录已验证：`flyway_schema_history` 跑到 8，10 张新表齐全）。
- 工作台统计与种子一致：在管老人 4、高危 2 / 低危 2、未闭环预警 2、闭环率 33%、随访完成率 60%、待签发方案 3。

## 八、已知限制

- 新版工作台以 `/api` 为准，旧的 Vue 页面（`/api/v1` + `app\web` 旧产物）已经被新版顶掉；旧接口还能调，但旧前端不再随包提供。
- 演示包里的 `app_setting.ai.apiKey` 还留着打包机的 Key，交出去之前记得到「系统配置」里点「清空 Key」，现场按需再填；清空后 AI 自动退回本地规则，流程不受影响。
- 自助注册只开给出院老人，医院主治医生、社区照护员的账号仍由管理员开通。

## 九、新增：AI 接力台（Agent + 本地知识库）

> 2026-11-17 追加。赛项评分里「Agent 工作流」与「RAG」这两块是我提的，要一条
> 「AI 自己决定下一步 + 结论必须有知识库出处」的链路，实现交给 AI 加进新版工作台；
> 原来的六个 AI 按钮没有换掉，全部保留当兜底。

### 9.1 和原来的区别

| | 原来的按钮 | AI 接力台 |
|---|---|---|
| 谁决定下一步 | 代码写死：读档案 → 拼 prompt → 调一次模型 | 模型自己选工具、自己决定调几次（最多 6 轮） |
| 知识从哪来 | 靠模型记忆，无法回查 | `kb_entries` 表 40 条康复规范，BM25 检索，结论带《文档》第 N 条 |
| 落库 | 直接写 | 生成「待确认动作」，医生点「确认执行」才写入 |
| 无 Key 时 | 该功能降级 | 降级为「规则编排」：同样的工具顺序跑一遍，标记 `mode=RULE` |

### 9.2 新增内容

- 迁移 `V10__station_agent_kb.sql`：建 `kb_entries`（8 篇文档、40 条规范），并给 `ai_logs` 加 `prompt_version`、`trace` 两列。
- `StationRagService`：BM25 检索（中文按相邻两字切词），返回 `{id, doc, section, title, snippet, score, citation}`，索引缓存 60 秒。
- `StationAgentService`：工具清单是 `get_elder_profile` / `list_open_alerts` / `assess_risk` / `search_kb` / `draft_rehab_plan`，循环调用 `AiGateway#chatMessage`，最后一轮解析 JSON 结论；`ai_logs.trace` 记下每一步。
- `StationAgentController`：提供 `POST /api/ai/agent/run`（返回轨迹 + 结论 + 引用 + 待确认动作）和 `POST /api/ai/agent/apply`（仅医生，逐条写 `plans` / `followups` / `records`）。
- 前端：医生和照护员的左栏新增「AI 接力台」，时间轴逐步展开，知识库命中出卡片，结论后面跟引用，动作勾选后再点确认执行。
- `AiGateway#chatMessage(cfg, messages, tools, maxTokens)`：带 `tool_calls` 的一轮对话。
